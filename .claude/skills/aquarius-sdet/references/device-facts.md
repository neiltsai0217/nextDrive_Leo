# 已確認的裝置/硬體資料事實

透過實機測試確認過的資料格式/慣例，記錄於此避免之後重新猜測或誤用。

## Cube (Athena) 韌體版本

- `ro.build.version.release` 的值（例如 `5.0.2008065`）即為韌體版本，跟 DB
  `eg3.public.gateways.fw_version` 存的格式一致。
- **版本字串不應該包含 `/`**；若出現，代表資料本身異常（不是正常會發生的
  格式），不需要為此加防呆邏輯——遇到應視為資料異常直接回報，而不是在程式
  裡加判斷去吞掉或自動處理一個「本來就不該發生」的情況。

## Cube J 配對與 Wi-Fi

- **待測閘道器要連 2.4GHz 的 SSID**（stage 用 `NextDrive2026_2.4G`）。2026-10-06 實測：選 5GHz 的
  `NextDrive2026` 時 App 配對單獨執行 8 次只過 1 次（藍牙連線 147 或「無法加入網路」），換成 2.4G 後
  手動 1 次、自動 3 次全過。為什麼 5GHz 會連帶讓藍牙連線不穩尚未查明。
- App 顯示的「發生錯誤 (147)」是 Android 藍牙的 `GATT_CONNECTION_TIMEOUT`：手機對閘道器的藍牙連線
  沒建起來，跟帳號、後端 API、Wi-Fi 密碼無關。失敗後 App 會回到同一個密碼視窗，可以原地重試。
- 短按設定鍵後**藍燈快閃 = 藍牙廣播中，可正常配對**（`led.ble.state=advertising`）；藍燈恆亮是按鍵前的
  待機狀態。
- App 在藍牙連線前就會先把閘道器註冊到帳號：配對中途失敗時，後端仍會留下關聯紀錄，要解除關聯才乾淨。

## 關聯狀態與上線 / 離線

- **線上的閘道器被解除關聯後約 13 秒內會自己重開機**，重開約 45～50 秒。緊接著下 adb 指令會失敗，
  要用 `wait_for_device_reboot()` 等它開完。閘道器離線時收不到通知，不會重開機。
- 重開機後 `/data/sendevent` 會不見，每次按鍵前要重新推上去（`_ensure_sendevent_binary()` 已處理）。
- **server 判定離線有延遲**：`wifi off` 斷網後實測 108～128 秒才把 `onlineStatus` 改成非 1；重新連網後
  約 12 秒回到 1。剛用 API 關聯完的幾秒內 `onlineStatus` 也還不是 1，斷網前要先確認已上線。
- 註冊 API（`device-management/v1/registrations`）不是冪等的：同一個 PID 重複註冊回 403。
